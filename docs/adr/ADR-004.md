# ADR-004 固定机性能门禁与基线重建规则

**状态**：Accepted

**日期**：2026-08-10

## 背景/Context

GitHub 托管 runner 的硬件与邻居负载不可控，不适合作为绝对性能阈值。宪法核心原则 IV 将 spec Success Criteria 定义为预算红线："性能回归等同于功能缺陷"，要求可重复、可阻断的绝对门禁。

## 决策/Decision

**固定参考机硬门禁**（research.md R18、plan.md D6、宪法原则 IV）：

- 参考机：固定 Apple M1 / 8GB；首次基线 MUST 记录并锁定准确的 macOS 与 WebView 版本。
- runner 标签固定为 `self-hosted`、`macOS`、`ARM64`、`excalidraw-perf`。
- 测量范围：聚合 Tauri 主进程及关联 WebView/GPU 进程的 RSS/CPU，分别测量冷启动、稳定空闲、10,000 图元场景、60 秒高频编辑与 30 分钟 soak。
- Intel Mac 与 Linux 仅归档非阻断趋势。

**绝对预算**（SC-002/013，P95 口径）：

| 预算 | 数值 |
|------|------|
| 冷启动至画布可编辑 | ≤ 2s |
| 空载应用进程树 RSS | ≤ 150MB |
| 空闲 CPU | ≤ 单逻辑核 1% |
| 10,000 图元场景稳定后进程树 RSS | ≤ 350MB |
| 30 分钟脚本编辑后 RSS 增长 | 同时 ≤ 50MB 且 ≤ 15% |
| 应用静置 60 秒 | 管理的数据目录与已挂载工作区零持续写入 |

**报告契约**：机器可读 JSON 报告记录 schemaVersion、commit、硬件型号、内存、准确的 OS/WebView 版本、样本、统计量、预算与 verdict；不记录机器唯一标识或秘密。

**基线重建规则**：runner 硬件、OS 或 WebView 版本变化即使原基线失效；必须附同负载测量证据并新增 ADR 显式重建；禁止通过提高阈值静默消除失败。

**执行门禁**：绝对性能预算在固定参考机上作为合并硬门禁执行（T090/T108，US1 合并/发布前必须 pass）；性能敏感 PR MUST 附带同机前后对比测量数据。

## 后果/Consequences

**积极**：

- 可重复的绝对预算硬门禁，性能回归在合并前被发现（等同功能缺陷）。
- 报告契约明确，verdict 可审计；基线失效自动触发重建流程。

**消极**：

- 需要维护专用固定机基础设施与校准流程。
- 参考机硬件/OS/WebView 升级会失效基线，需要重新测量并新增 ADR。
- 三平台同时硬门禁成本过高，当前仅 macOS 参考机阻断，Linux/Intel 覆盖滞后。

## 备选方案/Alternatives

- **托管 runner 绝对门禁**：硬件与邻居负载噪声高、误报多，被否。
- **仅报告不阻断**：无法执行预算红线，被否。
- **三平台同时硬门禁**：当前基础设施和校准成本过高，列为后续评估。
