# ADR-001 桌面框架选型：Tauri 2.x

**状态**：Accepted

**日期**：2026-08-10

## 背景/Context

Excalidraw Desktop 需要同时满足严格的性能预算（spec Success Criteria SC-002/SC-013：声明的 macOS 参考环境冷启动 P95 ≤2s、空载应用进程树 RSS P95 ≤150MB、空闲 CPU P95 ≤单逻辑核 1%，并约束大场景与长时内存增长）与高可靠性的持久化核心（原子写、SQLite、文件监听、路径 ACL）。框架选择直接决定预算是否可行，也决定安全模型与跨平台验证成本。

## 决策/Decision

采用 **Tauri 2.x**：Rust Core 承载后端，系统 WebView 渲染前端（macOS WKWebView / Linux WebKitGTK）。前端为 React 19 + TypeScript strict，后端为 Rust，业务代码不依赖 Node.js 运行时。

决策依据（research.md R1 / plan.md D1）：

| 维度 | Tauri 2.x | Electron |
|------|-----------|----------|
| 安装包体积 | 约 10–25MB | 约 80–200MB |
| 空载内存 | 约 30–80MB（预算 ≤150MB 有充裕余量） | 120–400MB（直接击穿 SC-002） |
| 冷启动 | <1s（预算 ≤2s） | 1–3s |
| 安全模型 | Rust 边界 + 细粒度 Capabilities，默认无 Node 暴露 | 需手工配置 Context Isolation |

可靠性核心能力（原子写、SQLite、文件监听、路径 ACL）在 Rust 侧实现最稳健；Tauri 2 Capabilities 提供默认最小权限的安全模型。资源预算由 T090/T108 在声明的 macOS 参考 VM 完整测量并保留真实 `pass`/`fail`；测量不作为框架决策或开源发布的硬门禁（见 ADR-004）。

## 后果/Consequences

**积极**：

- RSS、启动与包体预算留有余量，SC-002/SC-013 可重复验证。
- 原子写、崩溃恢复、冲突消解等数据可靠性路径由 Rust 实现，适合故障注入测试。
- 细粒度 Capabilities 与严格 CSP 构成默认最小权限模型（FR-031/032/033）。

**消极**：

- Linux WebKitGTK 存在发行版碎片化风险（WebKitGTK 版本、Wayland/X11、GPU 驱动、IME）；通过 Phase 0 跨发行版验证矩阵与 Phase 10 T094 Linux IME 矩阵对冲，失败项记录进支持平台清单。
- WKWebView 与 WebKitGTK 渲染存在差异，跨平台视觉一致性需额外验证。

## 备选方案/Alternatives

- **Electron**：渲染一致性最好、生态最全，但资源开销与启动速度不满足 SC-002/SC-013；安全模型需手工加固。
- **Wails (Go)**：NineRec 调研路线；Go 后端可行，但 Tauri 的权限模型、插件生态（single-instance、updater）与社区规模更适合生产级目标。
