## 概述

Excalidraw Desktop 是一款本地优先（Local-First）、完全离线可用的跨平台桌面白板应用，面向需要长期、可靠地创建和管理手绘风格图纸的用户（工程师、架构师、产品设计者、教育者）。产品以标准 `.excalidraw` 文件作为用户可见、可移植的事实来源，围绕它提供：不丢数据的编辑与保存体验、异常退出后的完整恢复能力、对外部文件变更的实时感知与冲突消解、面向大规模文件与大型画布的流畅性能，以及与操作系统深度集成的原生桌面体验（文件关联、单实例、多标签页）。

首发目标平台为 macOS 与主流 Linux 发行版。产品不包含实时协作、账号体系、云端同步或插件市场。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 离线创建、编辑与保存本地图纸 (Priority: P1)

用户在完全离线的环境中启动应用，新建一张图纸，使用完整的 Excalidraw 画布能力（图形、连线、手绘、文本、图片）进行绘制，随时手动保存或依赖自动保存，关闭后重新打开时内容与关闭前完全一致。保存产生的 `.excalidraw` 文件是标准格式，可被官方 Excalidraw 网页版或任何第三方工具直接打开。

**Why this priority**: 这是产品的最小核心价值——一个可靠的本地白板编辑器。没有它，其余能力都无从谈起。

**Independent Test**: 断开网络，完成"新建 → 绘制（含中文文本与图片）→ 保存 → 关闭 → 重新打开 → 内容一致 → 用官方网页版打开该文件验证兼容"的完整闭环。

**Acceptance Scenarios**:

1. **Given** 应用处于完全离线环境，**When** 用户启动应用并新建图纸进行绘制，**Then** 画布全部编辑能力可用，手绘字体、图形库资源正常加载，无任何因网络缺失导致的功能退化。
2. **Given** 用户已绘制内容且未手动保存，**When** 用户触发保存（快捷键或菜单），**Then** 内容立即写入目标 `.excalidraw` 文件，界面明确显示保存完成状态。
3. **Given** 用户持续高频绘制（拖拽、连笔手绘），**When** 编辑过程中，**Then** 画布保持流畅响应，不出现因保存或后台任务导致的可感知卡顿。
4. **Given** 一份由本应用保存的 `.excalidraw` 文件，**When** 用户以官方 Excalidraw 网页版打开该文件，**Then** 图形、文本、图片与样式完整呈现，无格式兼容错误。
5. **Given** 用户在画布中输入中文文本，**When** 文本渲染与导出时，**Then** 中文字符以与西文一致的手绘风格字体呈现，而非退化为系统默认字体。

### User Story 2 - 异常退出后不丢失编辑成果 (Priority: P1)

用户在编辑过程中遭遇应用崩溃、进程被强杀、系统断电或强制关机。重新启动应用后，系统检测到上次会话异常结束，提示用户存在比磁盘文件更新的未保存草稿，用户可选择恢复草稿、保留磁盘版本、将草稿另存为新文件或丢弃草稿。任何情况下，磁盘上已成功保存的文件绝不因保存过程被中断而损坏。

**Why this priority**: "高可靠性"是本产品区别于简单 Web 套壳方案的核心承诺。数据丢失或文件损坏是白板类工具最致命的信任破坏。

**Independent Test**: 在编辑中途模拟进程强杀与保存中途中断，重启应用验证：(a) 原文件始终可解析、内容完好；(b) 恢复提示出现且草稿内容与强杀前的最后编辑状态一致（误差不超过数秒的编辑量）。

**Acceptance Scenarios**:

1. **Given** 用户已编辑但未手动保存，**When** 应用进程被强制终止后重新启动，**Then** 系统检测到异常退出并弹出恢复对话框，展示草稿的保存时间与所属文档，提供"恢复草稿""保留磁盘版本""另存为新文件""丢弃草稿"四个选项。
2. **Given** 系统正在向目标文件执行保存，**When** 保存过程中发生断电或进程强杀，**Then** 重启后目标文件要么是完整的旧版本、要么是完整的新版本，绝不出现无法解析的半写文件。
3. **Given** 用户选择"恢复草稿"，**When** 恢复完成，**Then** 画布内容与异常退出前的最后编辑状态一致，丢失的编辑量不超过恢复能力承诺的时间窗口（见 SC-004）。
4. **Given** 某个恢复快照自身已损坏，**When** 恢复流程执行，**Then** 系统自动回退到更早的可用快照（每个文档保留多份轮换快照），并告知用户实际恢复到的时间点。
5. **Given** 应用正常退出，**When** 下次启动，**Then** 不出现恢复提示，且所有打开的文档已在退出前完成落盘。

### User Story 3 - 工作区文件管理侧边栏 (Priority: P2)

用户将某个本地目录挂载为"工作区"，在应用左侧的文件管理侧边栏中浏览该目录下的所有图纸文件，进行新建、打开、重命名、删除操作，并可同时以多标签页打开多份文档、在标签页之间快速切换，切换时各文档的未保存状态互不干扰。

**Why this priority**: 将应用从"单文件编辑器"提升为"图纸管理工具"，是桌面产品相对网页版的关键增值；但没有它单文件编辑仍可独立交付价值。

**Independent Test**: 挂载一个包含多级子目录与多份 `.excalidraw` 文件的目录，完成浏览、新建、重命名、删除、多标签打开与切换的全部操作闭环。

**Acceptance Scenarios**:

1. **Given** 用户选择一个本地目录作为工作区，**When** 挂载完成，**Then** 侧边栏以树形结构展示该目录下的图纸文件与子目录，目录内容变化后列表自动更新。
2. **Given** 侧边栏中的某个文件，**When** 用户执行重命名或删除，**Then** 文件系统中的真实文件同步变更，且已打开的对应标签页正确跟随（更名同步/提示已删除）。
3. **Given** 用户同时打开了多份文档标签页，**When** 在标签页之间切换，**Then** 每个文档的画布状态、未保存修改与撤销历史相互独立、互不丢失。
4. **Given** 工作区包含上万个文件，**When** 用户滚动与展开目录树，**Then** 侧边栏保持流畅（见 SC-007），应用内存不随文件总量线性暴涨。
5. **Given** 用户尝试通过侧边栏访问工作区之外的路径（如构造 `../` 路径），**When** 操作提交，**Then** 系统拒绝该操作，应用可访问范围严格限定在已挂载的工作区内。

### User Story 4 - 外部文件变更感知与冲突消解 (Priority: P2)

用户在应用外部修改了图纸文件——例如通过 Git 切换分支、云盘（iCloud/Dropbox）同步、或用其他编辑器直接编辑。应用实时感知这些变更：若当前文档无未保存修改则自动重载最新内容；若存在未保存修改则弹出冲突提示，由用户决定覆盖本地草稿、保留本地草稿或另存为新文件。任何情况下不发生静默覆盖。

**Why this priority**: 图纸文件天然会进入 Git 仓库与同步盘。缺乏外部感知会导致用户在多工具协作时静默丢失成果，直接违背可靠性承诺。

**Independent Test**: 打开一份文档后在外部用文本编辑器修改并保存该文件，分别在"应用内无修改"与"应用内有未保存修改"两种状态下验证自动重载与冲突弹窗行为。

**Acceptance Scenarios**:

1. **Given** 当前打开的文档在应用内无未保存修改，**When** 该文件在外部被修改，**Then** 应用在数秒内自动重载最新内容并提示用户已更新。
2. **Given** 当前打开的文档在应用内存在未保存修改，**When** 该文件在外部被修改，**Then** 应用弹出冲突提示，明确展示两个版本的时间信息，提供"以外部版本覆盖本地草稿""保留本地草稿""将本地草稿另存为新文件"三个选项，在用户选择前不写入目标文件。
3. **Given** 当前打开的文档对应的文件在外部被删除或移动，**When** 变更被感知，**Then** 标签页明确标示文件已不存在，用户可将当前内容另存到新位置，编辑成果不丢失。
4. **Given** 外部工具在短时间内对文件产生大量连续写入事件（如云盘同步），**When** 事件风暴发生，**Then** 应用合并处理事件，界面不出现反复重载或弹窗轰炸。

### User Story 5 - 图纸导出与分享 (Priority: P3)

用户将当前画布（或选中区域）导出为 PNG 或 SVG 文件用于文档嵌入与分享。导出结果在任何设备上打开都保持与画布一致的视觉效果，包括中文手绘字体风格。

**Why this priority**: 导出是白板成果对外交付的通道，属于成熟产品必备能力，但不阻塞核心编辑与可靠性价值。

**Independent Test**: 绘制包含中英文文本、图形与图片的画布，分别导出 PNG 与 SVG，在未安装相关字体的另一台设备上打开验证视觉一致性。

**Acceptance Scenarios**:

1. **Given** 一张包含图形、图片与中英文文本的画布，**When** 用户导出 PNG，**Then** 生成的位图与画布呈现一致，支持选择缩放倍率与背景（透明/纯色）。
2. **Given** 同一画布，**When** 用户导出 SVG，**Then** 生成的矢量文件在未安装手绘字体的设备上打开时，中英文文本仍保持手绘风格（字体随文件自包含）。
3. **Given** 导出目标路径不可写或磁盘空间不足，**When** 导出执行失败，**Then** 用户收到明确的失败原因提示，且不产生残留的不完整文件。

### User Story 6 - 原生桌面系统集成 (Priority: P3)

用户在系统文件管理器（Finder / 文件管理器）中双击 `.excalidraw` 文件，应用自动启动并打开该文件；若应用已在运行，则不启动新实例，而是在现有窗口中新开标签页并聚焦。应用以各平台的标准安装包形态分发，安装与启动符合平台安全规范，无系统安全警告。

**Why this priority**: 系统集成决定"桌面应用"的成熟度感知，但依赖核心编辑与文件管理能力先行。

**Independent Test**: 安装正式分发包，验证文件关联双击打开、二次打开复用实例、多文件连续打开各自成为标签页。

**Acceptance Scenarios**:

1. **Given** 应用已完成安装且未在运行，**When** 用户双击一个 `.excalidraw` 文件，**Then** 应用启动并直接打开该文件。
2. **Given** 应用已在运行，**When** 用户在系统中再次打开另一个图纸文件，**Then** 不启动第二个应用实例，现有窗口新开标签页加载该文件并置于前台。
3. **Given** macOS 用户下载官方分发包，**When** 安装并首次启动，**Then** 不触发"应用已损坏"或身份不明开发者的系统拦截。
4. **Given** 主流 Linux 发行版用户，**When** 通过对应格式的分发包安装，**Then** 应用出现在系统应用菜单，图纸文件图标与双击关联正确生效。

### User Story 7 - 多工作区与缩略图浏览 (Priority: P3)

重度用户同时挂载多个工作区目录（如"工作项目""个人笔记"），在侧边栏中并列管理；文件列表中的图纸显示内容缩略图，帮助用户快速定位目标文件而无须逐个打开。

**Why this priority**: 面向重度用户的规模化体验增强，建立在单工作区与侧边栏能力之上。

**Independent Test**: 挂载两个以上工作区，验证并列展示、独立移除；滚动包含大量文件的列表验证缩略图按需出现且不造成卡顿。

**Acceptance Scenarios**:

1. **Given** 用户已挂载一个工作区，**When** 用户添加第二个工作区目录，**Then** 侧边栏并列展示两个工作区的独立目录树，可分别折叠与移除（移除仅取消挂载，不删除磁盘文件）。
2. **Given** 文件列表处于可视状态，**When** 图纸文件滚动进入可视区域，**Then** 其内容缩略图在短暂延迟内出现；未进入可视区域的文件不消耗资源生成缩略图。
3. **Given** 文件内容未发生变化，**When** 用户再次启动应用或滚动回该文件，**Then** 缩略图立即从缓存呈现，无重复生成开销。

### Edge Cases

- **保存中途断电/强杀**：任何写入中断都不得留下无法解析的目标文件（见 US2 场景 2）。
- **磁盘空间不足**：保存或导出失败时给出明确提示，原文件保持完好，未保存内容保留在会话中等待用户处理。
- **打开损坏或非法的 `.excalidraw` 文件**：应用给出可理解的错误说明并拒绝加载，不崩溃、不将损坏内容写回。恶意构造的文件内容（如嵌入脚本的 JSON）不得获得任何本地系统能力。
- **超大画布（10,000+ 图元）**：编辑、平移、缩放保持可用帧率；自动持久化不因场景巨大而阻塞画布（见 SC-005/SC-006）。
- **长时间编辑与静置**：连续编辑不得造成无界内存增长；编辑停止并进入稳定空闲状态后，不得继续消耗显著 CPU 或持续写入应用管理的数据目录和已挂载工作区（见 SC-013）。
- **大体积图片重复粘贴**：同一图片在画布中多次出现时，文档体积与内存占用不随出现次数成倍增长（内容去重）。
- **同一文件被多个标签页/多次打开**：同一文件在应用内始终对应同一编辑会话，不产生同一文件的两个相互覆盖的编辑副本。
- **外部变更事件风暴**：云盘同步等高频事件被合并处理（见 US4 场景 4）。
- **符号链接与路径穿越**：工作区扫描正确处理符号链接循环，不陷入死循环；所有路径访问严格限定在已授权的工作区范围内。
- **Linux 平台差异**：不同发行版、显示协议（Wayland/X11）与输入法框架（Fcitx5/IBus）下，画布渲染与中文输入法候选框定位均在受支持平台清单上验证可用。
- **中文输入法组合输入**：拼音组合过程中的候选框位置紧随画布文本光标，组合事件不被吞失，不产生重复或丢失字符。
- **恢复快照自身损坏**：多版本轮换快照保证单个快照损坏时仍可回退（见 US2 场景 4）。

## Requirements *(mandatory)*

### Functional Requirements

#### 文档编辑与格式兼容

- **FR-001**: 系统 MUST 提供完整的 Excalidraw 画布编辑能力（图形、连线、自由手绘、文本、图片、框选、样式、撤销/重做），且全部能力在完全离线环境下可用。
- **FR-002**: 系统 MUST 以官方 `.excalidraw` JSON 规范读写文档文件；由本应用保存的文件 MUST 能被官方 Excalidraw 网页版无损打开，反之亦然。
- **FR-003**: 系统 MUST 支持 `.excalidraw` 与 `.excalidraw.json` 后缀的打开与保存；打开不受支持或损坏的文件时 MUST 给出明确错误提示且不崩溃。
- **FR-004**: 系统 MUST 内置覆盖中文（CJK 常用字符集）的手绘风格字体，中文与西文在画布渲染及导出产物中保持统一的手绘视觉风格；所有字体与静态资源 MUST 随应用打包，运行时不从网络加载。
- **FR-005**: 系统 MUST 支持在画布中通过系统输入法输入中文，输入法候选框位置 MUST 跟随画布上正在编辑的文本位置（含缩放与平移后）。

#### 保存、持久化与数据安全

- **FR-006**: 用户 MUST 能通过快捷键与菜单随时手动保存当前文档，保存完成与否的状态 MUST 在界面上明确可见（如"未保存修改"标识）。
- **FR-007**: 系统 MUST 自动持久化用户的编辑内容：编辑停止后数秒内草稿即达到可恢复状态，无须用户手动操作。
- **FR-008**: 对目标文档文件的任何写入 MUST 具备原子性：写入过程被任何方式中断（断电、强杀、系统崩溃）后，磁盘上的文件 MUST 保持为完整的旧版本或完整的新版本之一。
- **FR-009**: 系统 MUST 在文件落盘前校验待写入内容的结构完整性，禁止将不完整或不可解析的内容写入用户文件。
- **FR-010**: 自动持久化 MUST 与高频编辑解耦：持续绘制过程中不得以编辑事件频率触发文件写入，磁盘写入频率 MUST 通过防抖/合并控制在低频水平，且不造成画布可感知卡顿（跨进程序列化削峰见 FR-023）。
- **FR-011**: 在下列时机系统 MUST 将当前文档完整落盘到目标文件：用户手动保存、关闭或切换文档标签页、应用退出（阻塞式完成）、编辑静置达到设定阈值，以及自上次落盘起的最长等待上限到期。
- **FR-012**: 系统 MUST 检测异常退出（上次会话未正常结束），并在下次启动时向用户展示可恢复的草稿列表，提供"恢复草稿""保留磁盘版本""另存为新文件""丢弃草稿"选项；在用户决策前 MUST NOT 自动覆盖磁盘文件。
- **FR-013**: 系统 MUST 为每份打开的文档维护多份轮换恢复快照（至少 3 份），单个快照损坏时可回退至更早快照；快照 MUST 记录所属文档、保存时间与对应磁盘版本标识，用于恢复时的一致性比对。
- **FR-014**: 多份文档同时打开时，各文档的持久化 MUST 相互独立调度，不得因并发保存导致界面阻塞或文件写入相互干扰。

#### 工作区与文件管理

- **FR-015**: 用户 MUST 能将本地目录挂载为工作区，在侧边栏浏览其中的图纸文件与子目录；MUST 支持同时挂载多个工作区并可独立移除（移除不删除磁盘文件）。
- **FR-016**: 用户 MUST 能通过侧边栏完成图纸文件的新建、打开、重命名、删除；操作结果 MUST 与文件系统真实状态一致，且已打开的标签页正确跟随变更。
- **FR-017**: 系统 MUST 支持以多标签页同时打开多份文档，标签页之间的画布状态、未保存修改与撤销历史相互独立；同一文件 MUST 始终对应唯一的编辑会话。
- **FR-018**: 系统 MUST 实时监听工作区内文件的外部创建、修改、重命名与删除，并更新侧边栏；短时间内的高频事件 MUST 合并处理。
- **FR-019**: 当前打开的文件在外部被修改时：若应用内无未保存修改，系统 MUST 自动重载并提示；若存在未保存修改，系统 MUST 弹出冲突提示并提供"以外部版本覆盖本地草稿""保留本地草稿""另存为新文件"选项，用户决策前 MUST NOT 写入目标文件。
- **FR-020**: 当前打开的文件在外部被删除或移动时，系统 MUST 在界面上明确标示，并允许用户将当前内容另存至新位置。
- **FR-021**: 工作区目录扫描与索引 MUST 在后台执行，不阻塞界面；侧边栏在包含上万文件的工作区中 MUST 保持流畅滚动（按需渲染可视区域）。
- **FR-022**: 系统 MUST 为文件列表提供图纸内容缩略图：仅在文件进入可视区域时生成，结果按内容缓存，内容未变化时不重复生成。

#### 性能与资源

- **FR-023**: 高频编辑事件 MUST 仅更新内存状态；完整场景数据的序列化与跨进程传输 MUST 以低频批量方式进行（磁盘写入削峰见 FR-010）。
- **FR-024**: 画布中的图片资源 MUST 按内容去重存储：同一图片多次使用时磁盘与内存仅保留一份实体；对外保存/导出标准文件时 MUST 重新组装为符合官方规范的自包含格式。
- **FR-025**: 系统 MUST 在包含 10,000 个以上图元的场景下保持编辑、平移、缩放的可用流畅度（具体指标见 Success Criteria）。

#### 导出

- **FR-026**: 用户 MUST 能将画布或选中区域导出为 PNG（可选缩放倍率与背景）与 SVG；SVG 导出 MUST 自包含手绘字体，在未安装字体的设备上保持视觉一致。
- **FR-027**: 导出失败（路径不可写、空间不足等）时系统 MUST 给出明确原因，且不留下不完整的导出文件。

#### 系统集成与分发

- **FR-028**: 应用 MUST 注册为 `.excalidraw` 文件的打开程序：双击文件可启动应用并打开该文件；应用已运行时 MUST 复用现有实例并新开标签页聚焦，不启动重复进程。
- **FR-029**: 应用 MUST 以平台标准形态分发：macOS 提供经签名与公证的安装包（同时支持 Apple Silicon 与 Intel）；Linux 提供 AppImage 及 deb/rpm 包，正确注册应用菜单与文件图标。
- **FR-030**: 应用 MUST 在受支持平台清单（macOS 及声明支持的 Linux 发行版/显示协议组合）上完成画布渲染、拖放、剪贴板与中文输入法的真机验证。

#### 安全边界

- **FR-031**: 应用对本地文件系统的访问 MUST 严格限定于用户显式挂载的工作区目录与用户通过系统对话框显式选择的文件；MUST 拒绝一切越界路径访问（含 `../` 穿越与符号链接逃逸）。
- **FR-032**: 打开的文档内容 MUST 被视为不可信输入：恶意构造的文件 MUST NOT 获得越权的本地系统能力（脚本执行、越界文件读写、网络请求）。
- **FR-033**: 应用界面层 MUST NOT 在运行时从外部网络加载可执行代码；生产构建 MUST 启用严格的内容安全策略与最小权限配置。

### Key Entities

- **文档（Document）**: 一份用户可见的 `.excalidraw` 图纸文件，是内容的最终事实来源；具有路径、内容、修改时间与内容指纹，可被外部工具自由读写与同步。
- **工作区（Workspace）**: 用户挂载的本地目录，是文件管理与访问授权的边界；一个应用会话可同时持有多个工作区。
- **草稿（Draft）**: 某文档在应用内的最新编辑状态的持久化副本，服务于高频自动保存与崩溃恢复；对用户不可见，不承担可移植性职责，与目标文件通过内容指纹关联。
- **恢复快照（Recovery Snapshot）**: 按轮换策略保留的多份历史草稿副本，含所属文档、保存时间、对应磁盘版本标识与完整场景内容，用于异常退出后的多版本恢复。
- **图片资产（Image Asset）**: 画布中引用的图片实体，按内容指纹去重存储；导出标准文件时重新内嵌以保证格式兼容。
- **文档标签页（Tab）**: 一份文档在界面中的编辑会话载体，持有独立的画布状态、脏标记与撤销历史；同一文档至多对应一个活动会话。
- **会话锁（Session Lock）**: 标识应用运行会话的存活凭据，用于启动时判定上次会话是否异常结束并触发恢复流程。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在完全离线环境下，用户可完成"新建 → 绘制 → 保存 → 重开 → 导出"全流程，功能可用率 100%，与联网状态无差异。
- **SC-002**: 在固定 Apple M1 / 8GB 参考机上，清空应用测试数据后执行 10 次冷进程启动，进程启动至画布可编辑的 P95 不超过 2 秒；启动后稳定 30 秒，再于 60 秒采样窗口内聚合应用及其关联 WebView/GPU 进程，应用进程树 RSS 的 P95 不超过 150MB。首次基线 MUST 记录准确的 macOS 与 WebView 版本并随版本回归跟踪。
- **SC-003**: 自动化故障测试 MUST 对原子写全部可观察阶段进行参数化中断注入，至少覆盖临时文件创建、写入中途、临时文件同步、内容校验完成、替换前、替换后、父目录同步前与同步后；每个阶段中断后目标文件损坏率均为 0，文件始终可解析为完整的旧版本或完整的新版本。
- **SC-004**: 异常退出后，用户可恢复到距最后一次编辑不超过 5 秒的状态；恢复流程的引导对话框在下次启动时 100% 出现。
- **SC-005**: 包含 10,000 个图元的场景中，平移与缩放操作的界面响应保持平滑（典型交互不低于 30fps，目标 60fps），编辑操作无超过 100ms 的可感知冻结。
- **SC-006**: 持续高频绘制 60 秒期间，磁盘写入次数不超过编辑事件数的 1%（相对逐事件写盘降低 95% 以上），且期间画布无因持久化引起的掉帧尖峰。
- **SC-007**: 包含 10,000 个文件的工作区中，侧边栏滚动保持流畅（不低于 50fps），文件树展开响应不超过 200ms。
- **SC-008**: 外部修改已打开的文件后，应用在 3 秒内感知并作出响应（自动重载或冲突提示）；有未保存修改时静默覆盖的发生率为 0。
- **SC-009**: 含中英文混排文本的画布导出 SVG 后，产物 MUST 包含内嵌 WOFF2 字体且在未安装相关字体的固定干净渲染环境中无字体回退；使用 Playwright 固定截图基线比较时 `maxDiffPixelRatio` MUST 不超过 `0.001`。
- **SC-010**: macOS 正式分发包在全新系统上安装启动，0 次触发系统安全拦截；声明支持的 Linux 发行版上安装包全部可完成安装、启动与文件关联。
- **SC-011**: 同一图片在画布中重复使用 10 次时，文档存储体积相对单次使用的增幅不超过 5%。
- **SC-012**: 覆盖"保存中强杀""外部写冲突""损坏文件恢复"三类场景的自动化故障注入测试套件持续通过，用户原始数据在全部极端场景下零丢失。
- **SC-013**: 在固定 Apple M1 / 8GB 参考机上，应用稳定空闲状态的 CPU P95 不超过单逻辑核的 1%；10,000 图元场景稳定后应用进程树 RSS 不超过 350MB；30 分钟脚本编辑结束后，RSS 相对热身基线的增长 MUST 同时不超过 50MB 且不超过 15%；随后静置 60 秒期间，应用管理的数据目录和已挂载工作区 MUST 无持续写入。

## Assumptions

- **平台范围**: 首发支持 macOS（Apple Silicon 与 Intel）与主流 Linux 发行版（Ubuntu/Debian、Fedora 系，X11 与 Wayland）；Windows 不在本版本范围内，作为后续决策项。
- **产品边界**: 本地优先的单用户工具；实时协作、账号体系、云端同步、Excalidraw+ 云服务对接与插件市场均不在范围内。
- **格式策略**: 以官方 `.excalidraw` JSON 规范为唯一对外文档格式，不引入私有文档格式；应用内部的草稿与缓存不要求可移植。
- **上游集成策略**: 以官方 Excalidraw 编辑器组件作为标准依赖集成（非 Fork 上游应用仓库），通过适配层隔离上游版本演进，桌面业务逻辑不与上游内部 API 强耦合。
- **技术方向（工程假设，非产品需求）**: 研究文档论证的 Tauri v2 + Rust 后端 + React/TypeScript 前端、热层草稿库 + 冷层原子写文件的双层持久化、系统级文件监听等方案，作为满足上述需求的推荐实现路径，具体以实现阶段验证为准；本 PRD 的需求与成功标准均以技术无关方式表述。
- **中文字体**: 采用可自由再分发的开源中文手绘字体与官方手绘字体合并打包，许可证允许随应用分发与嵌入导出文件。
- **性能基线**: 固定 Apple M1 / 8GB 参考机执行绝对预算硬门禁；Intel Mac 与 Linux 当前仅记录非阻断趋势。参考机首次基线须锁定准确的 macOS 与 WebView 版本；任何硬件、OS 或 WebView 变更都使原基线失效，预算调整必须有测量证据和 ADR，禁止静默放宽。"零损坏、零静默覆盖、离线全可用"始终不可协商。
- **现有脚手架**: 按用户要求，本规格不受当前仓库中手工创建的 Tauri 模版代码约束，实现阶段可重构或替换。
- **单实例模型**: 应用以单实例多窗口/多标签模型运行；同一文件不支持在多个独立实例中同时编辑。
