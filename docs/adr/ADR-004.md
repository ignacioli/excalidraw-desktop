# ADR-004 声明参考环境的性能测量与基线分代规则

**状态**：Accepted（2026-08-12 修订）

**日期**：2026-08-10

## 背景/Context

项目需要用可审计的实测数据追踪 SC-002/SC-005/SC-006/SC-013 资源预算，同时避免把非营利开源项目绑定到维护成本较高的固定物理机。GitHub 托管 runner 的硬件与邻居负载不可控，不适合跨运行比较绝对阈值；不同宿主、虚拟化软件、客体 OS 或 WebView 的结果也不能直接混为同一序列。

宪法 v2.0.0 接受记录完整配置的目标 OS 虚拟机作为有效验收环境，并要求性能报告保留真实 `pass`/`fail`，但不把预算结果设为合并或开源发布的硬门禁。

## 决策/Decision

**声明参考环境测量**（research.md R18、plan.md D6、宪法原则 IV）：

- 第一参考环境：Apple M5 Pro / 48GB 宿主上的 Parallels Desktop Pro 26.4.1、macOS 26.5.2、4 vCPU / 8GB 虚拟机。
- 报告 MUST 记录宿主硬件、虚拟化软件名称/版本、客体 OS/构建号、WebView 版本、虚 CPU 数和客体内存；不得把 VM 结果描述为未实际执行的物理机覆盖。
- GitHub Actions runner 标签保持为 `self-hosted`、`macOS`、`ARM64`、`excalidraw-perf`，标签仅用于路由，不代表 Apple M1 真机或硬门禁。
- 测量范围聚合 Tauri 主进程及关联 WebView/GPU 进程的 RSS/CPU，分别测量冷启动、稳定空闲、10,000 图元场景、60 秒高频编辑与 30 分钟 soak。
- T090/T108 必须完整运行；完整报告的 verdict 必须是 `pass` 或 `fail`。预算失败作为可见的已知风险保留，不阻断合并或 GitHub Release。
- 其他 macOS、Intel Mac 与 Linux 环境可归档诊断趋势，但不得与第一参考环境直接比较绝对回归。

**绝对预算**（SC-002/013，P95 口径）：

| 预算 | 数值 |
|------|------|
| 冷启动至画布可编辑 | ≤ 2s |
| 空载应用进程树 RSS | ≤ 150MB |
| 空闲 CPU | ≤ 单逻辑核 1% |
| 10,000 图元场景稳定后进程树 RSS | ≤ 350MB |
| 30 分钟脚本编辑后 RSS 增长 | 同时 ≤ 50MB 且 ≤ 15% |
| 应用静置 60 秒 | 管理的数据目录与已挂载工作区零持续写入 |

**报告契约**：机器可读 JSON 报告记录 schemaVersion、commit、执行环境类型、宿主硬件、虚拟化软件/版本、客体硬件配额、准确的 OS/WebView 版本、样本、统计量、预算与 verdict；不记录机器唯一标识或秘密。

**基线分代规则**：宿主硬件、虚拟化软件/版本、客体 OS、vCPU/内存或 WebView 版本的变化会创建新的独立测量序列。变更 MUST 在报告与 ADR/验证汇总中显式记录；禁止混合不可比结果，也禁止通过提高阈值静默消除失败。

## 后果/Consequences

**积极**：

- 维护者现有 Parallels VM 即可执行完整 T090/T108，仍保留可审计的绝对预算与真实结果。
- 环境元数据明确，后续可以区分产品回归与宿主/虚拟化变化。
- 性能失败透明可见，但不会阻塞开源贡献与未签名 GitHub Release。

**消极**：

- VM 调度、宿主负载与虚拟 GPU 会增加波动；失败需要复测和分析，不能自动归因于产品代码。
- 第一参考环境不代表所有物理 Mac 或 Linux 设备；支持范围仍需独立的目标 OS 平台矩阵。
- 参考环境变化会开启新序列，长期趋势需要显式分代维护。

## 备选方案/Alternatives

- **固定 Apple M1 / 8GB 物理机硬门禁**：维护成本与非营利开源项目定位不匹配，被 2026-08-12 决策取代。
- **托管 runner 绝对门禁**：硬件与邻居负载噪声高、误报多，被否。
- **完全取消预算测量**：失去资源回归可见性，被否；项目保留完整 `pass`/`fail` 报告。
- **三平台同时硬门禁**：校准与维护成本过高，被否；其他环境仅建立独立诊断序列。
