# 版本历史性能测试摘要

这份摘要说明 0.4.0 所依据的本地性能测试结果。测试在 Apple M5 Pro 物理机上比较了加入本地版本历史前后的版本。VM 测试因 Parallels Desktop 不可用而跳过。

**结果是诊断数据，不是发布门禁：有些指标没有达到既定预算，产品负责人已接受当前结果和未完成根因归属的限制。** 这不代表所有性能预算均通过，也不能据此认定存在内存泄漏或确定性能变化由版本历史功能造成。

## 测试版本和口径

- **基线版本**：加入本地版本历史前的代码，提交 `babc027`。
- **候选版本**：加入本地版本历史后的代码，提交 `eb961ca`。
- **设备**：Apple M5 Pro、48 GiB 内存、macOS 26.6.2、WebKit 21624.5.1.11.3。
- **RSS** 是应用及其相关 WebKit 等进程占用的总内存；MB 按十进制计算。
- 下表的 PASS 标准沿用现有性能预算，没有为本次测量调整。

## 结果

表中“基线”和“候选”是各自测量值；结论按预先设定的 PASS 标准判断。

| 测试项目 | PASS 标准 | 基线版本 | 候选版本 | 结果 |
| --- | --- | ---: | ---: | --- |
| 启动到画布可编辑时间（P95） | ≤ 2,000 ms | 1,769.80 ms | 2,112.38 ms | 候选 FAIL |
| 空闲时总 RSS（P95） | ≤ 500 MB | 315.11 MB | 313.82 MB | 双方 PASS |
| 10,000 个图形时总 RSS（P95） | ≤ 950 MB | 613.83 MB | 1,366.77 MB | 候选 FAIL |
| 画布平移帧率 | ≥ 30 FPS | 59.98 FPS | 31.74 FPS | 双方 PASS；候选较低 |
| 平移时最长画面停顿 | ≤ 100 ms | 32 ms | 60 ms | 双方 PASS |
| 编辑时最长画面停顿 | ≤ 100 ms | 62 ms | 413 ms | 候选 FAIL |
| 每次脚本编辑对应的文件事件 | ≤ 0.01；本次各编辑 3,600 次 | 0 / 3,600 | 0 / 3,600 | 双方 PASS |
| 15 分钟编辑后的 RSS 增长 | 同时 ≤ 50 MB 且 ≤ 15% | +148.39 MB / +22.01% | +544.64 MB / +90.07% | 双方均 FAIL；候选增长更多 |
| 编辑结束后的空闲 CPU（P95） | ≤ 单逻辑核心的 35% | 12.3% | 15.6% | 双方 PASS |
| 编辑结束后的静置写入 | 60 秒内文件事件和变化路径均为 0 | 0 / 0 | 0 / 0 | 双方 PASS |
| History 恢复流程 | 1 次预热后完成 3 次 A→B→A 恢复检查 | 无 History 基线 | 3 次通过；P95 1,573.34 ms | 流程 PASS；无独立性能预算 |

**候选版本未达到的五个预算项**：启动时间、10,000 个图形时的总 RSS、编辑时最长画面停顿，以及 soak 的内存绝对增长和增长比例。后两项基线版本也未达到预算。

## 15 分钟持续编辑测试（soak）是什么

测试打开含 10,000 个图形的画布，先预热 30 秒，再采集 60 秒作为编辑前内存参考；接着脚本连续编辑 15 分钟，共执行 3,600 次编辑。编辑结束后等待 5 秒让保存操作完成，再采集 60 秒的空闲内存、CPU 和文件写入数据。

RSS 增长是“编辑后 60 秒空闲窗口的总 RSS P95”减去“编辑前参考窗口的总 RSS P95”。因此，本次说“基线 soak 超预算”，意思是**旧版本自身也超过了内存增长阈值**：增长 148.39 MB 且为 22.01%，两者均高于限制。候选版本的 544.64 MB 和 90.07% 也分别超过限制。它不是说测试设定的 soak 时长超过某个上限。

## 如何理解这些结果

本次结果表明，候选版本在启动时间、10,000 个图形时的内存、编辑停顿和持续编辑后的内存增长方面没有达到现有预算；平移帧率虽达到最低标准，但明显低于本次基线。由于每个版本只有一次有效配对，且运行间隔约 4 小时 52 分钟、没有控制其间的后台负载，这些差值不能单独证明根因或建立因果关系。

产品负责人已接受这些结果和未完成根因归属的限制，作为当前交付决定。**接受交付不等于性能指标 PASS，也不等于已经找到或修复性能原因。**
