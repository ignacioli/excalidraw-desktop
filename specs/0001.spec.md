## 1. 执行摘要

Excalidraw Desktop 面向需要长期、离线、可靠地管理绘图文件的用户，提供标准 `.excalidraw` 文档的创建、编辑、保存、恢复、冲突处理和导出能力。产品以用户可见的标准文件作为已提交版本，以应用专属草稿层降低异常退出造成的编辑损失；由 Rust 后端统一承担文件系统、持久化、恢复与安全边界，由 React/TypeScript 和官方 Excalidraw SDK 提供画布体验。

MVP 的核心承诺是：

1. 断网后仍可完成创建、打开、编辑、保存、重开及 PNG/SVG 导出。
2. 高频画布变更不会逐事件进行完整 Scene IPC 或覆盖目标文件。
3. 已成功保存的文件不会因已覆盖的保存失败路径变成半写 JSON；较新有效草稿可以恢复。
4. 外部程序、Git 或同步盘改变文件时，不静默覆盖本地或外部版本。
5. macOS 与声明支持的 Linux 环境经过真实 Tauri、WebView、CJK IME 和安装包验证。
6. 前端只能通过受控 IPC 使用必要的本地能力，生产构建启用非空 CSP 与最小 Tauri capability。

MVP 不复制 Excalidraw 云端产品，不包含实时协作、账号、云同步、插件市场或自动 Scene 合并。

## 2. 问题、目标与产品原则

### 2.1 问题陈述

简单地把 Excalidraw 网页放入桌面 WebView，无法满足高可靠桌面产品的要求：

- 高频 `onChange` 可能造成重复序列化、IPC 和文件写入，影响画布响应。
- 直接覆盖目标 JSON，可能在写入中断时留下不可解析文件。
- 崩溃、强杀或系统异常退出后，内存编辑可能丢失。
- Git、云盘或其他编辑器产生的外部变化可能与本地草稿冲突。
- WKWebView 与 WebKitGTK 在 Canvas、拖放、字体、剪贴板、Wayland/X11 和 IME 上存在差异。
- 当前仓库仍是基础脚手架，尚无编辑器、持久化、恢复、工作区、测试和发布能力。

### 2.2 产品目标

| ID | 目标 | 可观察结果 |
| --- | --- | --- |
| G-001 | 完成本地绘图闭环 | 用户可离线创建、打开、编辑、保存、另存、重开和导出文档 |
| G-002 | 保护用户数据 | 保存失败保留最后一个有效冷层版本；较新有效草稿可识别、可恢复 |
| G-003 | 保持交互流畅 | 高频编辑路径不逐事件写盘，并达到校准后的启动、输入、帧时与保存门槛 |
| G-004 | 正确处理外部修改 | 无脏编辑时安全刷新；有脏编辑时阻止覆盖并提供版本选择 |
| G-005 | 提供可验证的跨平台体验 | 发布矩阵内的 macOS/Linux 环境通过核心、IME、无障碍与分发验收 |
| G-006 | 建立安全桌面边界 | 严格 CSP、最小权限、Rust 侧路径与输入校验、隐私安全日志 |
| G-007 | 控制上游维护成本 | Excalidraw 集成集中在适配层，升级有契约与兼容语料回归 |

### 2.3 产品原则

- **本地优先**：核心工作流不依赖账号或网络，默认不上传文档内容。
- **标准格式优先**：用户文件保持标准 `.excalidraw` 可移植性；专有优化不得静默破坏兼容。
- **不静默丢失**：保存、恢复和冲突状态必须可见、可解释、可操作。
- **保守处理破坏性操作**：恢复为副本优先于覆盖；删除、覆盖、丢弃需要明确确认。
- **指标必须可复现**：每个性能结论记录硬件、OS、WebView、SDK、构建模式、夹具和样本量。
- **安全边界在 Rust**：不信任前端传入的路径、Schema、版本或大小声明。

## 4. 用户画像与关键旅程

### 4.1 用户画像

| Persona | 场景 | 核心需求 | 成功标准 |
| --- | --- | --- | --- |
| P1 个人知识工作者 | 架构图、会议草图、本地项目资料 | 快速启动、离线编辑、文件可见、自动保护 | 能理解并信任保存状态，可从 Finder/Nautilus 管理文件 |
| P2 重度画布用户 | 数千图元、图片、多标签、长时间编辑 | 平移缩放流畅、保存不阻塞、资源可控 | 在公开上限内性能可预测，无无界内存增长 |
| P3 CJK/Linux 用户 | 中文/日文/韩文、Wayland/X11 | 候选框正确、不丢字、不重复提交 | 声明支持的 IME 组合通过验收 |
| P4 可靠性敏感用户 | Git、云盘、脚本或其他编辑器同时修改 | 不静默覆盖、崩溃后恢复 | 冲突版本清楚，非破坏性选项为默认 |
| P5 发布与支持人员 | 构建、签名、公证、诊断和升级 | 可复现构建、版本化 Schema、脱敏日志 | 发布有门禁，诊断不含用户内容或敏感路径 |

### 4.2 关键旅程

#### J-001 首次使用与保存

1. 用户启动应用并选择一个工作区目录。
2. Rust 校验授权范围；拒绝时说明原因并允许重选。
3. 用户新建文档，系统建立文档 ID、内存状态和热层草稿。
4. 编辑即时反映在画布，草稿按调度策略低频持久化。
5. 用户保存时，系统先验证外部基线，再执行冷层安全替换。
6. 只有替换与验证成功后显示“已保存”；失败时保留旧文件与草稿。

#### J-002 崩溃恢复

1. 应用重启时读取会话状态和草稿，但不把单一锁文件存在等同于崩溃。
2. 系统比较草稿序号、基线哈希和当前冷层状态。
3. 若存在较新有效草稿，展示时间、来源与冲突信息。
4. 默认提供“恢复为副本”，另有“确认后覆盖”“丢弃”“稍后处理”。
5. 恢复写入失败时不删除草稿。

#### J-003 外部修改冲突

1. 打开或成功保存时记录内容哈希，并以 `mtime`/大小作为快速筛选。
2. watcher 触发重新检查；即使 watcher 未触发，保存前仍比较基线。
3. 无脏编辑时可安全刷新；解析失败则保留当前视图并报错。
4. 有脏编辑时暂停冷层保存，允许打开外部版、保留本地版另存或确认后覆盖。
5. MVP 不自动合并 Scene。

#### J-004 CJK 输入

1. 用户在缩放或平移后的画布开始文本编辑。
2. 输入承载元素随画布坐标定位，正确处理 composition 生命周期。
3. 合成期间画布快捷键不抢占，提交、取消、撤销不丢字或重复。
4. 导出使用已验证字体回退；不承诺所有外部 SVG 查看器像素一致。

## 5. 范围与优先级

### 5.1 MVP（Must Have）

- 标准 `.excalidraw` 的新建、打开、编辑、撤销/重做、保存、另存、重开。
- PNG/SVG 导出和标准兼容语料回归。
- 完全离线的编辑器、字体、图标和 Worker 资源。
- 多文档标签与单活动工作区；目录按需加载。
- 热层可恢复草稿、冷层安全替换、准确保存状态。
- 异常退出恢复；保存前外部版本检查与冲突 UI。
- 磁盘满、权限拒绝、损坏文件、取消另存、工作区不可访问等失败状态。
- 严格 CSP、最小 capability、Rust 侧路径/Schema/大小校验。
- 键盘闭环、焦点管理、非颜色唯一提示和基础屏幕阅读器支持。
- 发布矩阵内 CJK IME 正确性、macOS/Linux 原生冒烟和故障注入门禁。

### 5.2 Should Have

- 安全重命名与通过系统废纸篓或等价可恢复方式删除。
- 单实例接管、Open With 和基础文件关联。
- 用户主动导出的脱敏诊断包。
- 有明确资源预算的多候选恢复快照。

### 5.3 后续候选（Could Have）

- 多工作区、后台增量索引与搜索。
- 虚拟化文件树、低优先级缩略图队列与内容寻址缓存。
- 经许可与渲染验证的 CJK 手绘字体。
- 大场景增量 IPC；仅在全量快照无法达标后采用。
- 可逆的外置图片 CAS、文档历史、差异预览、自动更新和 Windows 支持。

### 5.4 明确非目标（Won't Have in MVP）

- 实时多人协作、账号、云同步、团队空间和分享链接。
- 完整 Fork 上游 PWA、插件市场或第三方脚本运行时。
- 自动 Scene 合并、CRDT、完整版本历史。
- 移动端与 Web 发布。
- 未解决标准文件兼容性和资产生命周期前的外置图片格式。
- 未完成签名、公证、更新源和回滚设计前的自动更新。
- “零数据丢失”“任何断电均安全”“支持所有 Linux 发行版”等绝对 SLA。

## 6. 功能需求

### 6.1 编辑器与文档

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-ED-001 | 建立 Excalidraw 适配层，封装初始化、Scene/资源加载、快照、变化订阅、导出及必要命令。 | 业务模块不直接依赖未声明 SDK API；SDK 升级通过契约和文档语料测试；版本可回滚。 |
| FR-ED-002 | 提供锁定 SDK 已支持的选择、绘制、文本、图片、撤销/重做、缩放和平移。 | 核心操作在平台矩阵和离线条件下通过；不承诺未锁定版本功能。 |
| FR-ED-003 | 支持多文档标签。 | 标签显示名称、脏状态和冲突状态；切换不丢内存状态；关闭脏标签必须提供保存、保留草稿或取消。 |
| FR-IO-001 | 标准文件往返。 | 合法文件可重开；损坏、超限或未来 Schema 不被原地覆盖；未知字段策略经 PoC 确定且不得静默丢失。 |
| FR-IO-002 | PNG/SVG 导出。 | 目标冲突需确认；失败不改变文档保存状态；产物可由目标查看器打开。 |
| FR-OFF-001 | 核心静态资源本地化。 | 断网冷启动后编辑、字体、Worker、保存、恢复与导出均不依赖远程请求。 |

### 6.2 工作区与文件管理

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-WS-001 | MVP 支持一个活动工作区。 | 只返回授权范围内的支持文件；扫描在后台执行；目录卸载或权限丢失有明确状态。 |
| FR-WS-002 | 文件树按需加载。 | 加载、空、拒绝、损坏和失败状态可区分；不得一次性渲染整个大型目录树。 |
| FR-WS-003 | 安全新建、重命名、另存与删除。 | 目标存在时不覆盖；脏文档操作需确认；删除默认可恢复，方案未定时不得永久删除。 |
| FR-SEC-002 | 路径授权在 Rust 侧执行。 | 防止 `..`、越权符号链接、大小写/Unicode 绕过和文件关联越权；新路径通过最近存在父目录安全验证。 |

### 6.3 双层持久化与保存

系统定义：

- **内存态**：当前编辑器即时状态。
- **热层草稿**：应用专属目录中的最新可恢复候选。
- **冷层文档**：工作区内用户可移植的标准已提交文件。

冷层是用户的已提交版本；热层序号更新时是恢复候选。二者合法分叉，UI 必须准确呈现。

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-PS-001 | 草稿包含稳定文档 ID、Schema 版本、单调序号、内容哈希、冷层基线哈希、更新时间、应用版本与脏状态。 | 同文档有序写入；旧请求不能覆盖新序号；Schema 迁移可回滚。 |
| FR-PS-002 | `onChange` 只即时更新内存/脏标记，按候选 300–500 ms trailing debounce 提交热层。 | 具体阈值由 PoC 校准；持续输入仍须有最大提交间隔；热层失败显示“未受保护”并允许重试/另存。 |
| FR-PS-003 | 手动保存、空闲、切换/关闭文档和正常退出请求可触发冷层检查点。 | 退出回调不是唯一保护；冷层成功前不清除脏状态；失败保留草稿。 |
| FR-PS-004 | 冷层执行同目录临时文件、完整写入、同步、重新校验、平台适配替换和必要的目录同步。 | 每个阶段可故障注入；失败后最后一个已提交版本仍可解析，且草稿不被清除。 |
| FR-PS-005 | 保存前比较磁盘内容与打开/上次保存基线。 | watcher 丢事件仍能检测冲突；无内容变化只更新元数据基线；外部删除不得被静默重建。 |
| FR-PS-006 | Beta 前将本地盘、系统同步目录、网络盘和 FUSE 分别标记为“正式支持”“尽力支持”或“不支持”。 | 正式支持类型通过完整故障矩阵；尽力支持类型显示限制并始终保留草稿；不支持类型以只读打开或要求另存到受支持位置，不静默降级保存。 |

不能把 `rename`/`fsync` 的本地文件系统语义推广到所有网络盘、FUSE 或同步盘。无法证明安全替换时，应用应保留草稿、阻止静默覆盖，并向用户说明限制。

## 9. 技术可行性与架构约束

### 9.1 前端与 Excalidraw SDK

方向可行，但资产路径、Worker、CSS、字体、导出和 WebKit 差异尚未验证。Phase 0 必须锁定 SDK 版本，在 macOS WKWebView 与目标 WebKitGTK 加载相同 Scene，验证完全离线资产，并采集 1k/5k/10k 图元及图片型 Scene 的性能。

全量 Scene 快照实现更简单可靠；只有基线不达标时，才以 ADR 启动 Worker 或增量 IPC，避免提前引入元素合并、顺序和恢复复杂度。

### 9.2 Rust、IPC 与存储

Rust 是持久化不变量的权威层。版本化请求至少包含文档 ID、提交序号、期望基线和 Scene；响应包含实际版本、哈希、状态和稳定错误码。同文档写入串行化，不同文档限制并发。应用退出不能依赖 WebView 最后一条异步消息，热层需在编辑期间持续存在。

SQLite WAL 是首选候选，不是既定结论。PoC 应与 redb 比较事务延迟、强杀恢复、迁移、并发读写、包体积和维护成本，并验证不同同步级别。

### 9.3 文件系统与监听

同目录临时文件加平台适配替换是基线方案，但需分别验证 APFS、目标 Linux 本地文件系统、同步目录、只读目录、磁盘耗尽、权限变化、文件锁和目标删除。watcher 只加速发现，冲突正确性依赖保存前指纹。

### 9.4 CJK 与字体

IME 正确性必须在真实系统测试，浏览器自动化不能代替。字体合并还需证明修改/分发许可、OpenType 表与基线正确、WOFF2 体积可接受、SDK 加载和 SVG 外部呈现可靠，因此不阻塞 MVP。

### 9.5 分发

Tauri 可打包不等于仓库已具备发布能力。正式分发依赖 macOS Developer ID、公证与秘密管理，以及 Linux 构建镜像、WebKitGTK 依赖和干净机安装测试。自动更新还需独立的签名密钥、迁移与失败回滚。

| R-004 | 网络/云盘不支持预期替换语义 | 中 | 极高 | 文件系统能力测试；不安全时保留草稿、限制覆盖或要求另存。 |

| R-006 | 热层引擎或配置不满足耐久目标 | 中 | 高 | 对比存储引擎与同步级别，执行强杀和迁移测试。 |
| R-007 | 快照占满磁盘或泄露敏感内容 | 中 | 高 | 配额、轮换、保留期、清理 UI 和隐私说明。 |
| R-008 | CJK 字体许可或体积不可接受 | 高 | 中 | MVP 使用系统回退；无许可证明不分发。 |
| R-009 | CSP 为空或 capability 扩张 | 高 | 高 | 配置测试与逐项评审；CSP 为空或权限过宽阻断发布。 |
| R-010 | SDK 升级破坏兼容或导出 | 中 | 高 | 锁版本、适配层、兼容语料和可回滚升级。 |

| R-013 | 超大文档或图片导致 OOM | 中 | 高 | 预检上限、可取消加载和有界拒绝；不能安全拒绝则阻断 GA。 |

## 11. 实施阶段与退出门槛

阶段不绑定研究文档中的固定周数；实际排期需在 PoC、团队容量和平台矩阵确定后估算。第 5 节定义的产品级 MVP 只有在 Phase 3 完成全部 Must 用户故事及 Gate A～F 后才成立；Phase 1 和 Phase 2 是内部 Alpha 增量，不得以“MVP 已完成”对外发布。

### Phase 0：风险验证与基线

交付：SDK 适配原型；macOS/Linux Canvas、IME、拖放、剪贴板与导出矩阵；性能夹具；SQLite/redb 对比 ADR；原子替换故障原型；CSP/capability 威胁模型。

退出门槛：关闭 D-001、D-003、D-004、D-006；至少一条保存/恢复原型在 macOS 和一个 Linux 环境运行；所有数字目标已有本仓库基线。

### Phase 1：核心功能 Alpha

交付：SDK 适配与本地资产；创建/打开/编辑/多标签/保存/另存/导出；单工作区；热层草稿；冷层安全替换；失败 UI；基础键盘与 CJK IME；前端、Rust 与 IPC 测试。

退出门槛：创建、编辑、多标签、标准文件、热/冷层保存、导出、键盘壳层和离线编辑子集通过内部验收；已测保存失败点不会使最后已提交文件不可解析。恢复、外部冲突和完整跨平台门禁尚未完成，因此本阶段不是产品级 MVP。

### Phase 2：高可靠性 Alpha

交付：会话状态与恢复候选；watcher、保存前指纹与冲突 UI；迁移/回滚；磁盘满、权限变化、删除、强杀故障测试；脱敏诊断；单实例/文件关联候选。

退出门槛：US-003～006 通过；可靠性门槛通过；静默覆盖为 0；恢复/覆盖 UI 通过键盘、屏幕阅读器与可用性评审。跨平台安装和完整发布矩阵仍在 Phase 3 收口。

### Phase 3：跨平台 MVP / Beta 与产品化

交付：macOS 签名、公证与干净机验证；选定 Linux 包；Wayland/X11、IME、GPU 与 WebKitGTK 矩阵；发布说明、隐私、数据位置、清理和诊断文档。

退出门槛：所有 Must 用户故事与 Gate A～F 通过；所有发布平台核心旅程通过；Gatekeeper 和 Linux 安装/升级/卸载通过；无 P0/P1 缺陷；产物可追溯且依赖安全门禁通过。达到此门槛后，产品才可标记为跨平台 MVP/Beta。

### Phase 4：后续增强

候选：多工作区、索引/搜索、虚拟文件树、缩略图缓存、CJK 手绘字体、图片去重、自动更新、Windows、文档历史。每项进入实现前必须有独立需求、迁移、安全边界和回退方案。

## 12. 验证策略

| 层级 | 验证范围 |
| --- | --- |
| 前端单元 | 调度状态机、脏状态、冲突/恢复 reducer、适配器契约、焦点管理 |
| Rust 单元 | 路径校验、Schema、哈希、错误分类、临时文件与快照轮换 |
| Rust 集成 | 存储迁移、事务顺序、安全替换、磁盘错误和并发写入 |
| IPC 契约 | 请求/响应版本、旧序号拒绝、错误码、恶意路径和超限输入 |
| 浏览器可见 E2E | 标签、侧边栏、保存状态、冲突和恢复 UI；不代替 Tauri 原生验证 |
| 原生桌面 E2E | 文件选择器、窗口生命周期、拖放、单实例、文件关联、快捷键 |
| 人工平台验证 | IME 候选框、屏幕阅读器、Wayland/X11、签名、公证、安装/卸载 |
| 故障注入 | 强杀、每个保存阶段、数据库锁、磁盘满、权限撤销、外部覆盖 |
| 兼容性语料 | 多 SDK Schema、CJK、图片、大 Scene、损坏和未知字段 |
| 性能回归 | 启动、帧时、长任务、序列化、IPC、存储、内存与文件树 |

最低故障场景包括：临时文件创建/写入/同步/校验/替换/目录同步失败；数据库提交失败或被锁；冷层成功但热层状态更新前终止；热层成功但冷层前终止；保存前/中/后的外部变化；工作区卸载或权限撤销；陈旧锁/PID 复用/损坏快照；Schema 升级中断；无网冷启动；composition 期间切换、撤销或关闭。

测试夹具不得包含真实用户数据；性能 Scene 固定随机种子与元素分布。不能通过减少场景、跳过平台或弱化断言让门禁通过。

## 14. 发布门禁

### Gate A：范围

- 所有 Must 用户故事通过；发布阻断决策关闭；偏差由产品、工程和质量负责人确认。

### Gate B：数据可靠性

- 保存故障注入、磁盘满、强杀、迁移、恢复和冲突测试通过。
- 静默覆盖为 0；不存在已知的假“已保存”路径。

### Gate C：性能

- 发布平台达到校准后的启动、输入、帧时、保存和内存门槛。
- 无无界内存增长；性能夹具进入持续回归。

### Gate D：安全与隐私

- CSP 非空且无远程脚本；capability 最小权限评审通过。
- 路径、不可信 JSON、超限输入和诊断包隐私测试通过。
- 无未处理的高危依赖漏洞，或存在批准的缓解与期限。

### Gate E：可访问性与 CJK

- 键盘闭环、焦点、错误提示和屏幕阅读器检查通过。
- 发布矩阵中的 CJK IME 用例通过；Canvas 已知限制准确披露。

### Gate F：跨平台与分发

- macOS 和选定 Linux 环境完成安装、启动、工作区、编辑、保存、恢复、冲突和导出旅程。
- 未测试平台不得标记为支持。
- macOS 签名/公证、Linux 干净机安装/升级/卸载及产物校验通过。
